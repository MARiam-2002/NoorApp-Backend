## 4. Android Gradle configuration

Do **not** blindly overwrite existing Gradle files. Modern Flutter projects usually apply plugins via `android/settings.gradle` (or `settings.gradle.kts`) and module `android/app/build.gradle` (or `.kts`).

### 4.1 Verify `applicationId`

In `android/app/build.gradle` (or `build.gradle.kts`), confirm:

```text
applicationId = "com.noor.app"
```

(or Groovy: `applicationId "com.noor.app"`)

This **must** match the Firebase Android app package.

Also check `namespace` if present — it can differ from `applicationId` in newer AGP, but **`applicationId` is what Firebase / Play care about for FCM registration**.

### 4.2 Google Services plugin

Verify the Google Services plugin is applied so `google-services.json` is processed.

Typical pattern (Flutter / AGP plugin DSL):

**`android/settings.gradle`** (plugin management / plugins block) — ensure Google Services classpath/plugin is available, e.g.:

```gradle
id "com.google.gms.google-services" version "4.4.2" apply false
```

(Use the version already present in the project if one exists; do not downgrade without reason.)

**`android/app/build.gradle`** — at the **bottom** (or in the plugins block, depending on project style):

```gradle
apply plugin: 'com.google.gms.google-services'
```

or:

```gradle
id 'com.google.gms.google-services'
```

If the project already applies this plugin, **leave it**. Only add it if missing.

### 4.3 Firebase / BoM dependencies

FlutterFire packages usually pull native Firebase SDKs. Prefer:

- Keeping FlutterFire versions from `pubspec.yaml` / FlutterFire CLI
- Not adding conflicting manual `firebase-messaging` versions in Gradle unless the project already does so intentionally

Verify after `flutter pub get` / Gradle sync:

- Build succeeds
- No duplicate Google Services plugin errors
- No “File google-services.json is missing” warning

### 4.4 Firebase initialization on Android

Native side is handled by FlutterFire once:

- `google-services.json` is in place
- Google Services plugin is applied
- `Firebase.initializeApp()` runs in Dart (see §6)

You do **not** hardcode Firebase credentials in Gradle.

## 7. Firebase Cloud Messaging (FCM) — Android

FCM is **backup** for Azan / general pushes. **Local Azan remains the primary alarm path.**

Backend sends Android notifications with:

```text
android.notification.channelId = "azan"
```

Flutter **must** create a compatible Android notification channel with id `azan` (importance high enough to alert), or system may suppress the notification UI.

### 7.1 Packages

Confirm `firebase_core` + `firebase_messaging` (see §5).

### 7.2 Notification permission

- **Android 13+ (API 33+):** request `POST_NOTIFICATIONS` / use `FirebaseMessaging.instance.requestPermission()` (and/or `permission_handler` if the app already uses it for Azan).
- Align with existing Azan permission UX — do not add a second conflicting permission flow if one already exists; extend it.

### 7.3 Android notification channel

Create channel id **`azan`** early (e.g. after Firebase init), matching Backend:

- id: `azan`
- importance: high
- sound: default (or product-specific if already defined)

If the Local Azan feature already created this channel, **reuse it** — do not create duplicates with different ids.

### 7.4 FCM token retrieval

After permission + Firebase init:

```dart
final token = await FirebaseMessaging.instance.getToken();
```

Then register with Backend (see §8).

### 7.5 Token refresh

Listen:

```dart
FirebaseMessaging.instance.onTokenRefresh.listen((newToken) {
  // POST /devices/fcm-token again for logged-in users
});
```

Also re-register after successful login.

### 7.6 Foreground messages

```dart
FirebaseMessaging.onMessage.listen((RemoteMessage message) {
  // Handle notification + data
  // Expect data['type'] == 'AZAN' | 'TEST' (and related fields)
});
```

Show a local notification if the UI should appear while the app is open (FCM often does not auto-display in foreground).

### 7.7 Background messages

Register a **top-level** (or `@pragma('vm:entry-point')`) handler **before** `runApp`:

```dart
@pragma('vm:entry-point')
Future<void> firebaseMessagingBackgroundHandler(RemoteMessage message) async {
  await Firebase.initializeApp(/* same options as main if required */);
  // Minimal work; respect existing architecture
}
```

```dart
FirebaseMessaging.onBackgroundMessage(firebaseMessagingBackgroundHandler);
```

### 7.8 Terminated state

On cold start:

```dart
final initial = await FirebaseMessaging.instance.getInitialMessage();
// If non-null, route / handle tap from terminated state
```

### 7.9 Notification tap / deep link

```dart
FirebaseMessaging.onMessageOpenedApp.listen((RemoteMessage message) {
  // Navigate using existing router; use data['type'] etc.
});
```

Preserve existing navigation / notification deep-link architecture from the in-app notifications module.

### 7.10 Expected data payloads (Backend)

| `data.type` | Meaning |
|-------------|---------|
| `TEST` | From `POST /devices/test-push` |
| `AZAN` | Prayer backup push from cron / reminder pipeline |

Also may include Arabic title/body fields in `data` (`titleAr`, `bodyAr`) alongside the notification title/body.

## 8. Backend FCM connection

### Relationship

```text
Flutter (Firebase client SDK)
  → obtains FCM registration token for device
  → POST token to Noor Backend

Backend (Firebase Admin SDK on Vercel)
  → stores token per user
  → sends pushes with Admin Messaging using the SAME Firebase project
```

Flutter never needs the Admin service account. Backend never needs `google-services.json`.

### Auth

All device endpoints require:

```http
Authorization: Bearer <accessToken>
```

Base URL (Production):

```text
https://noor-app-backend-one.vercel.app/api/v1
```

### Register token

`POST /api/v1/devices/fcm-token`

Body (supported):

```json
{
  "token": "FCM_TOKEN",
  "platform": "android",
  "locale": "ar"
}
```

Notes:

- `token` **or** `fcmToken` is accepted (at least one required).
- Optional: `platform`, `locale`, `appVersion`.
- Call after login, after `getToken()`, and on `onTokenRefresh`.
- Response includes `fcmConfigured` (whether Backend Admin can send). Registration can succeed even if send is temporarily off.

### Unregister token (logout / cleanup)

`DELETE /api/v1/devices/fcm-token`

Body must include the same token field(s):

```json
{
  "token": "FCM_TOKEN"
}
```

Call on logout **before** discarding the local session. Unregister is idempotent if the token is already gone.

### List devices (optional QA)

`GET /api/v1/devices`

### Test push

`POST /api/v1/devices/test-push`

Optional body:

```json
{
  "title": "Noor",
  "body": "Test notification",
  "titleAr": "نور",
  "bodyAr": "إشعار تجريبي"
}
```

Sends to all registered devices for the authenticated user with `data.type = TEST`.

### Flutter responsibility summary

1. Get FCM token from Firebase Messaging.  
2. Register with Backend while authenticated.  
3. Refresh registration when token changes.  
4. Delete token on logout.  
5. Handle `AZAN` / `TEST` without treating FCM as the only Azan path.

## 10. Service account warning (BACKEND ONLY)

The Firebase **Admin Service Account JSON** (private key) is **Backend-only**.

It must **NEVER** be placed in:

- `lib/`
- `android/app/`
- any Flutter source / asset folder
- GitHub (Flutter or Backend public trees) as a committed secret file

Backend loads credentials via environment variables / Vercel (for example):

- `FIREBASE_SERVICE_ACCOUNT_JSON`  
  **or**
- `FIREBASE_PROJECT_ID` + `FIREBASE_CLIENT_EMAIL` + `FIREBASE_PRIVATE_KEY`

Flutter uses only client config (`google-services.json` / FlutterFire options).

**This guide intentionally contains no real private keys or service-account JSON.**

## 16. End-to-end test procedure

1. **Run** the Flutter app on a real Android device (or Play-enabled emulator).  
2. Confirm logs show **Firebase initialization success** (no missing `google-services.json` / wrong options).  
3. **Request** notification permission; grant it.  
4. **Get** FCM token (`getToken()`); copy for debugging if needed (do not commit tokens).  
5. **Log in** to Backend (JWT).  
6. **Send** token:

   `POST https://noor-app-backend-one.vercel.app/api/v1/devices/fcm-token`  

   with body `{ "token": "...", "platform": "android", "locale": "ar" }` and Bearer token.  
7. Confirm Backend **accepts** (`success: true`, `registered: true`). Note `fcmConfigured`.  
8. Call:

   `POST https://noor-app-backend-one.vercel.app/api/v1/devices/test-push`  

   with Bearer token.  
9. Confirm the **test notification** reaches the device.  
10. **Foreground:** app open → message handled / local notification shown.  
11. **Background:** app minimized → system notification appears.  
12. **Terminated:** force-stop / swipe away → send another test → notification appears; tap opens app via `getInitialMessage` / open handlers.  
13. **Tap:** notification open routes correctly for `type=TEST` (and later `AZAN`).  
14. **Logout:** app calls `DELETE /devices/fcm-token` with the token.  
15. Confirm cleanup (`removed: true` or idempotent success); further test-push should report no devices / `sent: 0`.

Optional isolation: Firebase Console → Messaging → send test to the device token (proves client Firebase project without Backend).

## 17. Troubleshooting

For each issue: **CAUSE → CHECK → FIX**

### Firebase project does not match

- **CAUSE:** Client config or Admin credentials from `noor-app-mahmoud` (or other).  
- **CHECK:** `project_id` in `google-services.json` / `firebase_options.dart`; Backend env project id.  
- **FIX:** Re-download client config from `noorapp-d5d7d`; Backend must use Admin for the same project.

### `google-services.json` is missing

- **CAUSE:** File not at `android/app/google-services.json`.  
- **CHECK:** Path, filename, Android Studio / Gradle sync logs.  
- **FIX:** Place the file exactly under `android/app/` and rebuild.

### Wrong package name

- **CAUSE:** Firebase Android app package ≠ Gradle `applicationId`.  
- **CHECK:** Console package vs `applicationId`.  
- **FIX:** Make both `com.noor.app` (or re-register the Firebase app to match the real id — they must match).

### Firebase initialization failed

- **CAUSE:** Missing/wrong options, plugin not applied, corrupt JSON.  
- **CHECK:** `Firebase.initializeApp` error message; plugins; JSON validity.  
- **FIX:** Fix config / plugin; use options generated for `noorapp-d5d7d`.

### FCM token is null

- **CAUSE:** Init failed, Play services missing, wrong config, emulator without Google Play.  
- **CHECK:** Init logs; device type; `getToken()` error.  
- **FIX:** Use Play image / physical device; fix Firebase Android setup; retry after permission.

### Notification permission denied

- **CAUSE:** User denied; Android 13+ permission not requested.  
- **CHECK:** App info → Notifications.  
- **FIX:** Request permission in-flow; deep-link to system settings if permanently denied.

### Notification in background but not foreground

- **CAUSE:** Foreground does not auto-display notification UI.  
- **CHECK:** `FirebaseMessaging.onMessage` wired; local notification shown.  
- **FIX:** Handle foreground explicitly (local notifications / in-app UI).

### Notification not received at all

- **CAUSE:** Wrong project, no token registered, Backend `fcmConfigured: false`, wrong channel, OEM kill, permission off.  
- **CHECK:** `GET /health` / register response `fcmConfigured`; `GET /devices`; channel `azan`; device battery settings.  
- **FIX:** Align project; register token; ensure Backend Admin env; create channel; test on unrestricted device.

### Backend rejects FCM token

- **CAUSE:** Missing/short token; no Bearer auth; validation error.  
- **CHECK:** Request body has `token` or `fcmToken` (≥ 10 chars); `Authorization` header.  
- **FIX:** Send valid token after login; match API schema.

### Invalid Firebase credentials (Backend)

- **CAUSE:** Bad Admin JSON / private key escaping on Vercel.  
- **CHECK:** Backend logs; `health.fcm.configured`.  
- **FIX:** Ops fixes env (Flutter does not embed Admin keys).

### Wrong Service Account project

- **CAUSE:** Admin SA belongs to a different Firebase project than the client.  
- **CHECK:** SA `project_id` vs client `project_id`.  
- **FIX:** Use Admin credentials for `noorapp-d5d7d` only.

### Duplicate Firebase configuration

- **CAUSE:** Multiple `google-services.json`, mixed old options, two Firebase apps.  
- **CHECK:** Search repo for old project ids; multiple JSON files.  
- **FIX:** Remove stale config; keep a single `noorapp-d5d7d` client setup.

### Gradle / plugin compatibility errors

- **CAUSE:** Conflicting Google Services versions; plugin applied twice; AGP mismatch.  
- **CHECK:** Full Gradle error; `settings.gradle` + app module plugins.  
- **FIX:** Apply Google Services once; align plugin versions with current Flutter template / FlutterFire docs; do not delete unrelated plugins.
